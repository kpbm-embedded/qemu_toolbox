# 32_10_qemu: notes

## 2026-10-24: created
- New ID in the Box tool style (launcher `qemu-box`, generic part `lib/boxtool.bash` copied from
  32_06_renode; this copy is independent, the ID refers to nothing outside itself).
- QEMU: xPack qemu-arm 9.2.4-1 + qemu-riscv 9.2.4-1, all five platforms pinned with the sha256 from
  the `.sha` files xPack publishes next to each asset (the GitHub API was rate-limited at pin time).
- Toolchain: LLVM 22.1.8 from conda-forge (clang, lld, llvm-tools, lldb) instead of xPack GCC
  (Arm 1.1 GB + RISC-V 1.6 GB extracted). clang 23 was tried first; lldb tops out at 22 on
  conda-forge, so everything was pinned to 22 (one libLLVM, ~300 MB less).
- conda-forge `gdb` 18.1 is configured for the host only (`set architecture armv7e-m` fails), so
  the debugger is lldb (`gdb-remote`). The first doctor run reported the host's /usr/bin/gdb;
  doctor and `qemu-box gdb` now use the env's lldb explicitly.
- Mistake: `pixi clean` (to drop the unused LLVM 23 packages) removes `.pixi/envs`, not the
  package cache; the env was regenerated by `qemu-box bootstrap` (nothing user-made lost, but it
  bypassed trash-put). The package cache (cache/pixi, ~1.4 GB) still holds the LLVM 23 packages;
  `qemu-box clean --all --yes` trashes it if space matters.
- Generic fix in this copy of boxtool.bash: `cmd_new` aborted under `set -e` when the last
  template file was not executable (`[ -x ] && chmod` as the loop's last statement); curl in
  `fetch_pin` is quiet (`-fsSL`).
- Results: install ok, doctor 18 ok / 0 failed, examples test 5/5, tests/test_smoke.sh 7/7,
  tests/test_dry_run.sh 27/27 (incl. shellcheck of 11 scripts).
